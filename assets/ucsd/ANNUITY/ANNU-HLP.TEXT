ANNUITY - Apple Pascal 1.3
==========================

ANNUITY.TEXT is ordinary ASCII source text with LF line endings.
It has no UCSD text header, no block padding and no special encoding.
All source comments, prompts and report labels are in English.
The name ANNUITY is the English translation of ANNUITEIT.

Target: Apple Pascal 1.3 on an Apple II with 128 KB.
No PDF library, JSON parser or other third-party runtime is required.
The source uses Apple/UCSD long integers for exact cent arithmetic.

BUILD AND RUN
-------------
Import the supplied plain source into your Apple Pascal development
setup using the HOST.CODE program

Command: X(ecute:
*:host
HOST> get annuity.text t
GET ANNUITY.TEXT: .... done
HOST> Quit

then compile ANNUITY
with the Apple Pascal compiler. Use the standard Apple Pascal library
and linker when requested for long-integer arithmetic. Run the resulting
program using the system Execute command.

The supplied source is deliberately NOT an already encoded Apple disk
file or disk image. Copying its bytes directly into a native Pascal
volume without your usual text import (HOST with optien "T") is not 
the same as importing it.
No precompiled executable is supplied.

Keep the program and its data on a writable work volume and select that
volume as the default prefix before running. Unqualified filenames use
that prefix; the program cannot discover its executable's directory.
Apple Pascal uses volumes, so no per-loan subdirectories are required.

On first use, the saved-loan list is empty. Choose N to create a loan.
The list shows each loan's human-readable name, rather than requiring
the name to be a valid disk filename. Choose its number to open it.

INPUT
-----
- Amounts: 15000, 15000.00 or 15000,00; no thousands separators.
- Rates: annual percentages, at most two decimal places, 0 through 100.
- Gift percentage: an annual rate on the same balance as interest;
  it must not exceed the interest percentage.
- Dates: DD-MM-YYYY, for example 15-10-2026.
- Q cancels numeric/date input. A blank new-loan name cancels creation.
- Names and descriptions: at most 80 characters; use ASCII text.
- Maximum 50 loans, with at most 100 extra payments per loan.
- Maximum individual amount: EUR 999999999.99.
- Original term: 1 through 1200 months. Supported dates: 1900-9998.

PAYMENT MODES
-------------
1. Constant principal repayment:
   The original capital divided by the original term, rounded to cents.
   Extra payments shorten the term; they do not reduce the regular
   principal repayment. Interest is additional. The final payment clears
   the remaining principal, including any rounding remainder.

2. Interest only:
   Regular principal repayment is zero. Interest, gifts and extra payments
   are still calculated. The schedule stops at the original term or when
   extra payments have cleared the debt. A remaining balance is reported;
   it is not silently cleared or turned into a final repayment.

3. Fixed total payment:
   The entered monthly amount INCLUDES interest. Principal repayment is
   the monthly amount minus that month's interest. The original term no
   longer limits the schedule. Payments stop when the balance reaches zero,
   and the final regular payment may be lower. Extra payments are additional
   to the regular payment. A total below interest is rejected; interest is
   never silently capitalized. A total equal to interest without any future
   extra payments is rejected because it cannot repay the loan.

Changing mode recalculates the entire schedule from the original start.
A change is validated before it is saved. If it fails, the previous loan
remains selected with its previous settings.

EXTRA PAYMENTS AND INTEREST
--------------------------
Extra payments may occur on any calendar day, including the start date.
They reduce the balance from that day, before interest for that day.
Multiple payments on the same date are allowed. They are sorted by date,
then amount. Each applied payment is capped at the remaining balance.
After the loan is paid off, later payments are not applied or reported.
The planned amount remains stored for future recalculations. The remove
menu shows planned amounts; the schedule/report shows APPLIED amounts.

In constant-principal and interest-only mode, extra dates must fall within
the original term. Remove any payments beyond that term before switching
back from fixed-total mode. No extra date may precede the loan start.

Interest = sum(balance in cents x applicable calendar days) x annual
percentage / (1200 x days in this calendar month), rounded to cents.
The first month counts only from the start date. Regular principal is paid
at month end, after interest is calculated. The gift uses the same daily
balances and is rounded separately. Rounding is half up.

Net principal = regular principal repayment minus gift. It can be negative.
Extra payments are shown separately, not included in net principal.
The gift rate is a calculation input, not a determination of tax exemption.

MENUS AND REPORTS
-----------------
1 Schedule: shows each month, applied extras and all amounts.
2 Add extra: records a dated planned extra payment.
3 Remove extra: shows planned payments and removes the selected entry.
4 Text report: writes/replaces the selected loan's report after confirmation.
5 Payment mode: chooses any of the three modes above.
6 Description: replaces the description; blank cancels, '-' clears it.
7 Back: returns to the loan list.
0 Quit: exits the program.

Schedules use vertical rows for readability on a 40-column display.
The display pauses after every 20 output lines; press Return to continue.
A report includes the name and description at the top. Each month shows
interest, principal, net principal, extra, balance and gift. YEAR TOTAL
rows contain summed flows and the closing balance, followed by a blank
line. The partial final year is included, followed by GRAND TOTAL.
Plain text has no bold or font-size controls, so year headings are uppercase.

FILES
-----
LOANS.TEXT       Loan index: numbers and human-readable names.
INDEXBAK.TEXT    Index before the most recent new-loan registration.
L0001.TEXT       Loan 1, including description and planned extra payments.
B0001.TEXT       Loan 1 before its most recent saved edit.
R0001.TEXT       Loan 1's generated text report.
L0002.TEXT etc.  Files for subsequent loans.

Names fit the Apple Pascal filename limit. Do not rename individual files
without updating the administration. No JSON files are used. Extras are
stored inside the corresponding loan file, so loan data and extras remain
one consistent record. The program reads them automatically when selected.

The running Apple program uses Pascal TEXT file I/O. Its disk files use
the host Pascal runtime's text representation; this is separate from the
ordinary ASCII format of the source file supplied with this package.

Back up the work volume periodically. Before editing an existing loan the
program saves its previous state as Bnnnn.TEXT. A backup-write failure
prevents the new loan write. Disk errors are reported. Writes are not a
power-failure-safe transaction: after a disk failure, restore Lnnnn.TEXT
from Bnnnn.TEXT if necessary. For an index failure, restore LOANS.TEXT
from INDEXBAK.TEXT; a newly created Lnnnn.TEXT may remain unregistered.

VALIDATION STATUS
-----------------
See TESTS.TXT. The supplied source compiles with a UCSD p-System
crosscompiler targeting Apple. Calculations and interactions were exercised
using a mechanically adapted Free Pascal test build. The actual Apple
Pascal 1.3 compiler, runtime, disk system and physical 128 KB machine have
not been exercised here. Verify native compilation and disk I/O on your
setup before entering your live loan administration.
